## 目指すところ

**AI が書いたコードを見て、翻訳されずに、何をしているか分かる。必要なら、直してほしい所を指して頼める。**

書けるようになることは目指さない。**読めるようになること**を目指す。
最後の目印は二つ：

1. 五十行くらいの実物を渡されて、「これは、何を受け取って、何を確かめて、何を返す（残す）のか」を日本語で言える
2. 「この関数の、この行の、この条件を、こう変えてほしい。理由はこう」と頼める

期間は決めない。一日十分。目安では、四〜五か月で2まで届く。遅れてかまわない。急ぐほうが遠回りになる。

## 一日の形（十分）

```
二分　前の日の「一問」の答え合わせ（帳を読んで、先生から一つだけ聞く）
五分　新しいこと一つ。短いコードを読む → 何が出るか予想して言う → 動かして確かめる
三分　自分の言葉で一行（「今日の一行」）。先生が帳に書き留める
```

**芯は「予想してから、動かす」**。読む力は、予想が外れたところで育つ。外れたら、それがその日の収穫。
動かす前に、必ず予想を言ってもらう（当てなくていい）。

- 道具：Chromebook の Linux の窓（ターミナル）で `python3` と打つと、Python が対話で動く（`>>>` が出る）。終わるときは `exit()`
- 携帯しか無い日は、**読むだけの日**にする（先生が結果を見せる）。それでも予想は先に言う
- 新しい言葉は、一日に一つまで
- コードは十行以内。riverwave に書かせすぎない（目的は読むこと。打つのは、一行写すくらいでいい）

## 一週の形

- 六日 進む＋一日 ふりかえり（その週のコードを五行ほど読んで、一行ずつ日本語にする）

## 段（目安。進み具合で先生と造が動かす）

例は、なるべく島と帳簿から取る。riverwave がもう知っているものに、名前と形を付けていく。

### 第一段　Python に触る（一週目）

| 日 | すること | 例 |
|---|---|---|
| 1 | `python3` を開いて、閉じる。`print` は画面に出す | `print("こんにちは、島")` |
| 2 | 数と文字は違う | `print(2 + 3)` と `print("2" + "3")`——予想が分かれる所 |
| 3 | 名前を付ける（変数）。名前は「箱」ではなく「札」 | `belly = 10` → `belly = belly - 1` → `print(belly)` |
| 4 | エラーを読む。**いちばん下の行がいちばん大事** | `print(bely)`（綴り違い）→ `NameError` |
| 5 | `#` から後ろは、人のための書き込み（コメント） | 島のコードのコメントを一つ見せる |
| 6 | ふりかえり | 五行を一行ずつ日本語に |

### 第二段　値と名前（二〜四週目）

- 文字（`str`）・数（`int`, `float`）・本当か嘘か（`True`/`False`）
- 比べる（`==` と `=` は違う、`<`、`>`）
- **リスト**＝並び。持ち物：`items = ["りんご", "どんぐり"]`、何番目（**0から数える**）、`len`、足す（`append`）
- **辞書**＝名前と中身の組。`fig = {"who": "衡", "form": "鹿", "color": "灰"}`、`fig["color"]`
  ——ここで `姿.md` の下の一行を見せる。「これ、辞書だったのか」となる所
- 辞書の中のリスト、リストの中の辞書（`置かれた姿.md` の `avatars` がまさにそれ）

### 第三段　流れ（五〜八週目）

- **もし**（`if` / `elif` / `else`）。字下げ（行頭の空白）が「どこまでがその中か」を決める
  例：`if belly < 3: print("お腹がすいた")`
- **くり返し**（`for`）。持ち物を一つずつ見る。`for item in items:`
- **関数**（`def` と `return`）。「名前の付いた手順」。受け取るもの（引数）と、返すもの
  例：`def eat(belly, food):` → りんごなら +2
- 関数の中の if、if の中の for——**組み合わせを読む**。ここで初めて二十行ほどの塊を読む
- `while` は読めればいい（「〜のあいだ、くり返す」）

### 第四段　形とファイル（九〜十二週目）

- ファイルを読む（`open`）。**実物：`田んぼ.md` を読んで、```json の一行を取り出す**
- `json` で辞書にする（`json.loads`）。島がしていることを、自分の手でやってみる
- `import`——人の作った道具を借りる
- **`assert`**——「こうなっているはず」を確かめる行。島の検査（`tests/`）はこれでできている

### 第五段　実物を読む（十三〜十六週目）

- エラーの全文（traceback）を、下から上へ読む
- **差分（diff）を読む**。`-` が消えた行、`+` が足された行。AI が「直しました」と言ったとき、何が変わったかを自分で見る
- **頼み方の練習**。「〜の関数の、〜の行。今は〜になっている。〜にしてほしい。理由は〜」を、毎週一つ書く
- クラス（`class`）は、読めればいい（「設計図と、そこから作った一つ」）

### 第六段　橋——川床の実物へ（十七週目〜）

**いちばん近い実物は、AIPlayground（澪が一手ずつ観測しながら変えていく世界）**。そこが Python で書かれているなら、ここまでの読み方がそのまま使える。
この段のはじめは、澪が自分で書いたコードを、澪と一緒に読むところから。

**もう一つの注意**：川床で造が書いているコード——箱庭の島（`index.html`・`visit.js`）も、汀瀬（`.gs`）も——は、Python ではなく **JavaScript** で書いてある。
でも、読む力の八割は言語をまたいで使える（名前・値・もし・くり返し・関数・リスト・辞書）。違うのは書き方の癖だけ：

| Python | JavaScript |
|---|---|
| `def eat(food):` | `function eat(food) {` |
| 字下げで中を決める | `{` と `}` で中を決める |
| `belly = 10` | `var belly = 10;` |
| リスト `[...]`・辞書 `{...}` | 配列 `[...]`・オブジェクト `{...}`（ほぼ同じ） |
| `True` / `None` | `true` / `null` |

## 先生（澪）への手引き

1. **一度に一つ**。新しい言葉は一日一つ
2. **予想が先**。答えは、予想を聞いてから
3. **間違いは測定値**。外れた予想・エラーは、その日いちばんの収穫として扱う
4. 書かせすぎない。目的は読むこと
5. 比喩で説明したら、必ず実物のコードに戻る
6. 分からないと言われたら、速さを落とす。進まなくていい
7. 毎回、帳を読んでから始める。終わったら帳に書く
8. 測ってから、言う——澪の一言のとおりに。riverwave が分かったかどうかは、本人の「今日の一行」で測る
